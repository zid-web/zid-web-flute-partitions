# CLAUDE.md

Application React + Vite + TypeScript (PWA) empaquetée avec Tauri 2. Français partout dans l'UI.

- Tests : `npm test` (vitest), `python3 -m unittest discover -s .claude/skills/imslp-flute-curator/tests` et `python3 -m unittest discover -s .claude/skills/omr-notes/tests`.
- OMR d'une partition à relire (Audiveris → .mxl → MuseScore .mscz + PDF de contrôle) : skill `omr-notes`, sorties dans `skill-work/omr-notes/`.
- Typecheck : `npm run typecheck`. Build web : `npm run build`.
- La logique de suivi de partition reste **pure** dans `src/lib/follower.ts` (pas d'audio ni de DOM) et testée.
- Hauteurs : numéros MIDI ; OSMD : octave 1 = octave MusicXML 4 (`noteToMidi` dans `src/lib/score.ts`).
- Partitions : uniquement via le skill `imslp-flute-curator` ou `scripts/make_samples.py` ; `public/scores/catalog.json` est **généré** (`curate.py catalog`), la CI vérifie qu'il est à jour.
- Jamais d'identifiants IMSLP dans le dépôt : variables d'environnement `IMSLP_USERNAME` / `IMSLP_PASSWORD`.
- Ne garder que des partitions domaine public / CC (pas de NonCommercial sans accord explicite).
- Hors ligne obligatoire : aucune fonction ne doit **dépendre** du réseau, pas de police ni de script externes. Seules exceptions, facultatives : la recherche de mise à jour (`src/lib/appUpdate.ts`, service worker ; `src/lib/nativeUpdate.ts` pour l'application de bureau) et, dans les applications natives, la synchronisation du catalogue depuis Vercel (`src/lib/contentSync.ts`).
- Son « Écouter » : vraie flûte enregistrée (`src/lib/sampler.ts`, `public/samples/flute/`, VSCO-2 CE en CC0, préparée par `scripts/flute_samples.py`) ; `src/lib/synth.ts` ne sert que si les échantillons ne se chargent pas.
- « Ma flûte » : notes enregistrées par l'utilisateur (`src/lib/myFlute.ts`, analyse pure et testée), gardées sur l'appareil (IndexedDB `flute-ma-flute`, stockage persistant demandé), jamais envoyées, incluses dans la sauvegarde 💾 (version 2, son en 16 bits base64 ; `src/lib/saveFile.ts` : commande native `save_backup` → Téléchargements dans Tauri, partage sur mobile, téléchargement sur ordinateur) ; « Uniquement ma flûte » (par défaut) : toutes les notes jouées depuis l'enregistrement le plus proche, sinon prioritaires à ±3 demi-tons pour « Écouter ».
- Accompagnement (piano et/ou 2ᵉ flûte d'un duo) : l'élève joue la 1ʳᵉ flûte ; le reste est gardé à l'import (`StoredScore.accompaniment`) ou publié par le robot (`<id>.accomp.musicxml`, `accompanimentFile` + `partners` dans le catalogue), tempo recopié ; l'application le joue et le fait suivre le jeu au micro : `src/lib/accompanist.ts` (pur et testé) joue en continu, en anticipant, au tempo mesuré sur les attaques de la flûte (`ScoreFollower.lastOnsetMs`, calées sur l'heure de sortie audio `getOutputTimestamp`), et attend la flûte juste après la note attendue.
- Piano : à l'import, les parties de piano sont repérées (`src/lib/accompaniment.ts`, pur et testé) — flûte + piano = accompagnement qui suit le jeu au micro, piano seul = écoute ; vrai piano `src/lib/piano.ts` (`public/samples/piano/`, Salamander Grand Piano CC-BY 3.0, `scripts/piano_samples.py`, crédit obligatoire).
- Mises à jour : jamais d'installation pendant un morceau (`setBusy`), uniquement depuis la bibliothèque. Application de bureau : `tauri-plugin-updater` (`src/lib/nativeUpdate.ts`, bandeau dans la bibliothèque), `latest.json` signé sur la dernière Release GitHub publiée ; clé publique dans `tauri.conf.json`, clé privée uniquement dans le secret `TAURI_SIGNING_PRIVATE_KEY` (jamais dans le dépôt).
- Difficulté : `difficulty.py` (skill) et `src/lib/difficulty.ts` (import dans l'app) doivent rester identiques ; le test d'import le vérifie sur `catalog.json`.
- Partitions importées : uniquement sur l'appareil (`src/lib/userScores.ts`, IndexedDB), jamais envoyées sur un serveur.
- IMSLP bloque les téléchargements automatiques (« Bot Check ») : ne jamais chercher à le contourner ; les PDF passent par le dépôt manuel `content/a-convertir/` (workflow « Conversion des partitions déposées »).
- Pas de connexion directe de l'application à IMSLP : le catalogue passe par le workflow « Curation IMSLP » et une pull request validée.
- Tessiture : à l'import, les notes injouables à la flûte (hors Si3–Ré7) sont ramenées à l'octave jouable (`src/lib/fluteRange.ts`, pur et testé) ; les partitions déjà importées le sont à l'ouverture (`withPlayableOctaves`).
- Mouvements : une œuvre importée en un fichier par mouvement est regroupée (`src/lib/movements.ts`, pur et testé : titre d'œuvre + numéro de mouvement MusicXML, ou nom de fichier `.mvt2`, `- 2`) ; « Écouter » enchaîne les mouvements en gardant le même contexte audio.
- Import de PDF : uniquement dans l'application pour ordinateur, avec Audiveris installé (commandes natives `audiveris_path` / `convert_pdf` dans `src-tauri/src/lib.rs`, `src/lib/pdfImport.ts`) ; rien n'est envoyé. Les parties « Voice » d'Audiveris sont remises en ordre système par système (`adoptOmrFlute` dans `src/lib/import.ts` : la flûte = première partie gravée du système, attribut `width`). Conversion page par page, plusieurs Audiveris à la fois (`worker_count`, jamais le mode parallèle interne d'Audiveris, dont l'export échoue), page bloquée abandonnée après 6 min, bouton Annuler (`cancel_pdf`) ; les pages sont rassemblées par `src/lib/omrPages.ts` (pur et testé), pages sautées signalées ; partition d'orchestre (≥ 6 parties) : conseil d'importer la partie de flûte seule. Avancement (barre + %) : Rust lit le journal d'Audiveris et émet `omr-progress` (`PAGES n`, `PAGE_START n`, `PAGE_DONE n ok|fail` + étapes), `src/lib/omrProgress.ts` (pur et testé) le traduit en pages × étapes.
- Bibliothèque : onglets Tout / Mes partitions / Bibliothèque, grille ou liste, œuvres en plusieurs mouvements sur une carte (`src/lib/libraryView.ts`, pur et testé), suppression annulable quelques secondes.
- Outils de travail (lecteur) : décompte (une mesure de clics), boucle sur des mesures avec tempo progressif (+4 après un passage sans faute et ≥ 70 % à l'heure), évaluation du rythme (en avance / à l'heure / en retard, d'après le tempo de l'élève) : `src/lib/practice.ts`, pur et testé.
- Bilan de justesse (fin de morceau, passages en boucle) : écart moyen en cents par note tenue, attaque ignorée (`src/lib/intonation.ts`, pur et testé).
- Mode Écouter : points d'orgue (×1,8), rit./rall. (jusqu'à 70 % du tempo), accel., a tempo, de la partie de l'élève et de l'accompagnement (`src/lib/expressive.ts`, pur et testé : `timeWarp`) ; le jeu au micro n'est pas déformé (l'accompagnement suit déjà l'élève).
- Correction de notes (partitions importées, bouton ✏️ du lecteur) : la note touchée est retrouvée par mesure, position et hauteur (`src/lib/noteEdit.ts`, pur et testé), ½ ton / octave / silence, notes liées comprises, dans la tessiture ; enregistrée aussitôt sur l'appareil (`updateUserScoreXml`), annulable.
- Import en arrière-plan : la file d'import vit hors des écrans (`src/lib/importJobs.ts`, testé) — on peut ouvrir une partition ou « Ma flûte » pendant la conversion, une pastille (`ImportIndicator`) suit l'avancement, les fichiers ajoutés attendent leur tour ; pas de mise à jour de l'application pendant un import.
- Écouter : les notes (mélodie, piano, 2ᵉ flûte) sont programmées au fil de l'eau, quelques secondes à l'avance (`src/lib/noteStream.ts`, testé) — jamais tout le morceau d'un coup (une partition d'orchestre figeait l'application) ; pas d'étalement `...tableau` sur des listes de notes (limite d'arguments).
